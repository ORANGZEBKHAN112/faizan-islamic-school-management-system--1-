
Course Selling Module
نئے ERP میں Course Selling کے نظام کے لیے Functional Proposal
پس منظر
Faizan Islamic School System میں Courses کی فروخت کیمپس کے ذریعے کی جاتی ہے، جبکہ Head Office میں Project Lead پورے Course Selling Project کی نگرانی کرتا ہے۔
موجودہ نظام میں Projection، Purchase Order، Warehouse سے ترسیل، Campus Receiving، Inventory، Course Sale، Payment Verification، Course Issue اور Reports کا بڑا حصہ Manual طریقے سے چل رہا ہے۔ 
 Project Lead کو مختلف Excel Files، Warehouse Invoices، ERP Reports اور Finance Reports کو الگ الگ دیکھ کر صورتحال معلوم کرنا پڑتی ہے، جس سے وقت زیادہ صرف ہوتا ہے اور Data میں فرق اور Human Error کے امکانات پیدا ہوتے ہیں۔
موجودہ Flow
Projection → Purchase Order → Warehouse Dispatch → Campus Receiving → Course Set → Course Sale → Voucher → KuickPay Payment → Course Issue → Record
نئے ERP میں مطلوبہ نظام
نئے ERP کا مقصد Course Selling کے پورے عمل کو ایک مربوط نظام میں لانا ہے، تاکہ Project Lead کو Sales، Payment، Inventory، Course Issuance اور Reconciliation کی صورتحال ایک ہی جگہ دستیاب ہو۔

Project Lead کے لیے Campus-wise اور Class-wise Projection کا ریکارڈ موجود ہو، جس کی بنیاد پر Purchase Order تیار ہو۔

Purchase Order کو ERP سے Excel / PDF میں حاصل کیا جا سکے اور Warehouse کو بھیجا جا سکے۔
Campus Receiving & Inventory
Warehouse سے Course موصول ہونے پر Campus اپنے متعلقہ Order کو ERP میں دیکھ کر Quantity کی Verification کرے۔
ای آرپی پر  Verification کا بٹن دیا جائے کورس اسٹاک کیمپس کو وصول ہونے پر کیمپس  کورس کی ویریفیکشن ڈیجٹلی دے جس سے معلوم ہو سکےکہ وئیر ہاؤس سے جاری کیا گیا کورس مکمل بھیجا گیا ہے /کم بھیجا گیا ہے وغیرھما۔ 
Verify کا Button ہر Title کے لیے الگ ہونا چاہیے، جبکہ تمام جگہوں پر Title Sequence ایک جیسا ہو۔
 اسی طرح ہر Report میں Title Names یکساں ہوں اور Warehouse کے Record سے مکمل طور پر Match کرتے ہوں۔
Dispatched Quantity → Received Quantity → Difference
کی بنیاد پر Receiving کا Record بنے۔ 
Verification کے بعد Campus Inventory Update ہو۔
Inventory

Region → Campus → Class → Course / Title → Quantity
Project Lead پورے پاکستان کے تمام Campuses کی موجودہ Inventory ایک مرکزی جگہ سے دیکھ سکے۔

کیمپس سے Software کے ذریعے Course Issue کرتے وقت Admission Number کے تحت Voucher میں درج Titles کے مطابق ہی Titles Issue کیے جائیں، تاکہ Customized Voucher کی صورت میں مکمل Course Issue ہونے کا خدشہ نہ رہے۔ اس طریقۂ کار سے Inventory کا درست Balance بھی برقرار رہے گا۔
Issue کے بٹن میں Full Courseیا Customizeکا Hintبھی دیا جاسکتا ہے۔
Course Shuffling / Campus-to-Campus Stock Transfer
اگر کسی Campus میں کسی Course کا Stock کم ہو تو دوسرے Campus کے Available Stock سے Requirement پوری کی جاتی ہے۔
مثلاً شاہ فیصل Campus کو KG کے 05 Courses درکار ہوں اور بلدیہ ٹاؤن Campus کے پاس اضافی Stock موجود ہو تو 05 Courses بلدیہ ٹاؤن سے شاہ فیصل منتقل کیے جائیں۔
ERP میں Course Shuffling کا مکمل Record:
Request → Approval → Dispatch → Receiving → Inventory Update

Course Voucher:
Bulk Admission
Individual Student
Existing Student

Voucherمیں Student، Admission Number، Class، Campus، Course / Titles، Quantity، Price، Total Amount، Voucher Number، Due Date اور Payment Status موجود ہوں۔
Parent، KuickPay کے ذریعے Payment کرے اور Payment Status ERP میں Update ہو۔
ای آرپی پر  Course Issued کا بٹن دیا جائے فیس کی ادائیگی کے بعد كورس جاری کیے جانے پر اس طالب علم کے اسٹیٹس کو اپڈیٹ کیا جائے  جس سے معلوم ہو سکے اس طالب علم کو کورس جاری کیا جا چکا ہے۔
Course Issue & Inventory Deduction
Course Issue کے وقت Admission Number کے ذریعے Student کا Record، Class، Voucher، Payment Status اور Available Stock verify ہو۔
Payment Paid ہونے اور Stock Available ہونے کی صورت میں Course Issue کا Record بنے۔
اگر Stock Available نہ ہو تو Voucher Generate کرتے وقت ہی واضح Notification/Alert موصول ہو، تاکہ Campus بروقت Course/Title arrange کرنے کے لیے اقدامات کر سکے۔
Complete Course Set Issue ہونے پر Set میں شامل تمام Titles کی Quantity Inventory سے خودکار طور پر کم ہو۔
مثلاً:
Class 5 Complete Set Issue
→ Book A -1→ Book B -1→ Book C -1→ Book D -1
اس طرح Course Issue اور Inventory ایک ہی Transaction سے مربوط رہیں۔

محفوظ ہو۔
